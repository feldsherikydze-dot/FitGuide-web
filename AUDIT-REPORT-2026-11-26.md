## 1. Паритет генератора Android ↔ веб

**Что проверяли.** Одинаковые входные данные должны давать одинаковую
программу: те же упражнения, подходы, веса, фазы. До аудита паритет на
матрице не сверялся (в журнале от 1.70 числился открытым).

**Стенд.** В `%TEMP%\opencode\parity`:
- настоящий Java-`ProgramGenerator` из release-классов APK, запущенный на JVM
  через заглушки Android API (`org.json`, `R`, `android.*`), — логика не
  переписывалась;
- веб-генератор (`parity-web.mjs`) на той же матрице;
- матрица 140 кейсов: 6 целей × 3 уровня × 5 дней, плюс типы программ,
  периодизация, дом/зал, акценты, female, upper/glutes, senior, беременность.

**Найденные причины расхождений (все подтверждены прогоном):**

| № | Где | Суть | Фикс |
|---|-----|------|------|
| 1 | Android `DataProvider.levelRank` | не знал уровень `новичок` → считал ранг 3 и исключал новичковые упражнения у новичков | добавлен `новичок` = 1 |
| 2 | Веб `difficultyRank` | `элита` считалась рангом 1, `средний–продвинутый` — рангом 3 (в Android наоборот) | ранги приведены к Android: `новичок/начинающий/beginner`=1, `средний/средний–продвинутый/intermediate`=2, `продвинутый/элита`=3 |
| 3 | Android `ProgramGenerator` | `phase.deload` никогда не выставлялся → в JSON и бэкапе всегда `false` | `phase.deload = deload` |
| 4 | Java `pick` / веб `pick` | `seed + saltHash + phaseIndex*7` переполняет Java `int`; JS считал в double — база выбора упражнения уезжала | в вебе `settingsSeed` и `base` считаются с `\|0` (32-битное переполнение, как в Java), `floorMod` сохранён |

**Проверка после фиксов:** `android cases: 140`, `web cases: 140`,
`compare2.mjs` → **matched 140, mismatched 0**.

**Файлы:** `FitGuide-web/src/core/generator.ts`,
`FitGuide-web/src/core/exerciseIndex.ts`,
`FitGuide2/app/src/main/java/com/fitguide/app/DataProvider.java`,
`FitGuide2/app/src/main/java/com/fitguide/app/ProgramGenerator.java`.

## 2. Безопасность данных при импорте

**Что смотрели:** `dataPort.ts` (импорт/экспорт, точка возврата),
`crossPort.ts` (конвертер Android-бэкапа), `store.ts` (гидратация zustand),
`SettingsPage.tsx` (пикер файла и диалог импорта).

**Найдено и закрыто:**

1. **Нет предела размера файла.** Гигантский JSON парсился в память и мог
   подвесить вкладку. Теперь `MAX_BACKUP_BYTES = 20 МБ`: проверка и в
   `inspectBackup()` (ошибка `too-big`), и в пикере до чтения файла (тост
   «Файл слишком большой — резервная копия не больше 20 МБ»).
2. **Служебные имена ключей.** Ключи `__proto__`, `prototype`, `constructor`
   из файла больше не попадают в `localStorage` — ни при импорте, ни при
   откате, ни в счётчике «Ключей» в диалоге. Глобальный прототип не
   загрязняется (проверено `({}).polluted === undefined`).
3. **Частичная запись при переполнении quota.** Раньше импорт мог упасть
   посередине: часть ключей новая, часть старая. Теперь при любой ошибке
   записи вызывается `restoreSafetyBackup()` — снимок «до импорта»
   возвращается целиком, недописанные ключи убираются.
4. **Неполный откат.** `restoreSafetyBackup()` раньше только дописывал ключи
   из снимка, оставляя данные, появившиеся после него. Теперь сначала
   удаляются все `fitguide_web_*`, кроме самого снимка, потом снимок
   записывается заново — откат действительно возвращает состояние «до».

**Тест:** node + esbuild, фейковый `localStorage` с управляемой ошибкой
quota — **14 OK, 0 FAIL**: обычный импорт, `__proto__` не пишется, прототип
цел, safety-копия снимается, quota → полный откат (старый профиль на месте,
посторонний ключ из снимка восстановлен, недописанный убран), откат убирает
лишние ключи, файл больше 20 МБ отклоняется.

**Что осталось осознанно:** импорт по-прежнему заменяет все данные веб-версии
(это его смысл), а не сливает с текущими. Android-файл сохраняет веб-настройки
(палитра, заставка, часы) — поведение 1.15.30 не менялось.

## 3. E2E: онбординг → программа → тренировка → журнал → анализ → экспорт/импорт

**Стенд:** Playwright WebKit, профиль iPhone 13 (390×844, DPR 3, touch,
ru-RU), preview-сборка 1.15.33 на `localhost:4173`, чистый профиль.

**Сценарий и результат — 11 шагов, 0 ошибок консоли и pageerror:**

1. Заставка → «Старт» → онбординг открылся.
2. Онбординг: имя, возраст, рост, вес → «Готово»; профиль в
   `localStorage` появился, переход на главную.
3. Генерация программы: «Сгенерировать программу» → экран «Мои программы»,
   в хранилище 1 программа.
4. Открытие программы → первый день → экран тренировки с параметрами
   `program/week/day`.
5. Скрининг красных флагов — «Всё в порядке», если показан.
6. Подход: «Начать» → «Подход выполнен» → диалог фактических повторов
   «Дальше» → оценка «Тяжело» → отдых «Пропустить».
7. Завершение: «Завершить» → «Тренировка завершена!» → «Сохранить»;
   сессия в `coach_state` (sessions = 1), переход в тренера.
8. Журнал: запись видна, вкладки «Журнал/Рекорды/1ПМ/Тело/Анализ» на месте.
9. Анализ: экран построился, текста 908 символов, ошибок/краша нет.
10. Экспорт: скачался `fitguide-web-2026-11-26.json`, 24 064 байта.
11. Импорт: файл выбран, диалог распознал версию/дату/ключи, «Импортировать»
    → «Перезапустить»; профиль и программа на месте, посторонний маркер
    `fitguide_web_audit_marker` исчез — импорт действительно заменяет данные
    целиком, как и задумано.

**iOS-метрики на финальном экране:** ширина документа 390 = ширине окна 390
(горизонтального скролла нет); полей с шрифтом меньше 16px — 0 из 0 на
экране настроек; `100dvh` поддерживается; `-webkit-backdrop-filter`
поддерживается.

**Оговорка.** WebKit Playwright — тот же движок, что в Safari, и он ловит
JS/CSS-несовместимости, но это не настоящий iOS Safari: нет системных
жестов, PWA-режима «на экран Домой», особенностей сборки WebKit в iOS.
Финальная проверка на живом iPhone остаётся за владельцем, когда появится
устройство.

## 4. Производительность и вес

- `dist` — **22,88 МБ**, из них `downloads` (6 APK) — **20,11 МБ**,
  `assets` — 0,97 МБ.
- JS-бандл — **888,34 КБ** (275,40 КБ gzip), CSS — 49,15 КБ (9,38 КБ gzip).
  Vite предупреждает о чанке >500 КБ — это предупреждение, не ошибка;
  на телефоне первый экран грузится из кэша SW.
- Service Worker **не прекеширует APK**: в `STATIC_ASSETS` только оболочка,
  база упражнений, звуки и иконки. Скачивание APK — отдельный запрос только
  со страницы загрузки.
- Старые APK 1.70–1.72 (3,50 + 3,51 + 3,51 МБ ≈ **10,05 МБ**) в `dist`
  лежат без ссылок: `download.html` ведёт на `FitGuide.apk`,
  `update.json` — на `FitGuide-1.74.apk`. Удалить их можно без последствий,
  но это релизные файлы, поэтому жду подтверждения владельца.
